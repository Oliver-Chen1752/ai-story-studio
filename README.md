# Ai故事工坊 · AI 互动故事创作器

> 从一段设定出发，AI 生成开篇与分歧选项，创作者逐条展开分支并维护跨分支一致性，
> 最终把作品变成一条**可以真正点击通关**的互动故事。

## 一、我解决的问题

**目标用户**：写互动叙事 / 分支短剧的独立创作者。

**核心痛点**：分支叙事的真正成本不在"写文字"，而在两件事——

1. **结构指数爆炸**：每个选择都分裂出新分支，写到中后期没人记得清哪条路走通了、哪条是死路。
2. **跨分支一致性**：A 线里死掉的角色，B 线里不能莫名复活；前面埋的伏笔，后面得有人收。

这两件事靠人脑维护，规模一上来就崩。所以我没有去做"AI 帮你写小说"，
而是去做**AI 帮你扛住分支结构**——这是我认为最有价值、也最能体现 AI 杠杆的切口。

**我的取舍**：与其做一个覆盖电影/短剧/漫画的大平台，不如把"分支故事"这一个切片做到**真的能玩通关**。
交付边界因此定为：一条完整可用的创作→试玩闭环，而不是一堆半成品功能。

## 二、产品是怎么运作的

完整用户路径（**已端到端跑通**）：

```
① 填设定（世界观/主角/前提/基调）
   → ② AI 生成开篇 + 2~3 个带"后果暗示"的分歧选项
   → ③ 对任一选项点「AI 续写」→ 生成子节点（自动携带故事圣经，保证一致性）
   → ④ 编辑 / 重roll / 收为结局
   → ⑤ 结构面板实时显示故事树，✦ 一键诊断死路·孤立·单薄
   → ⑥ 切「▶ 试玩」从头点击通关
   → ⑦ 保存到本地作品库，可重新载入继续创作
```

界面分三块：左侧**故事树画布**（创作）、右侧**结构面板 + 故事圣经**（掌控全局）、
顶部一键切**试玩模式**（验证成果）。

## 三、AI 如何参与（四个真实调用点）

| 能力 | AI 做了什么 | 为什么人工做不好 | 真实性 |
|---|---|---|---|
| **开篇生成** | 从设定产出带钩子的开场 + 分歧选项，选项自带后果暗示 | — | ✅ DeepSeek |
| **分支续写** | 把「故事圣经」（角色卡+伏笔+已读路径）注入上下文再写下一节点 | 跨分支一致性靠人脑记不住 | ✅ |
| **结局收束** | 回应这条路径上埋的伏笔，给出四种结局类型之一 | 收束要"记得前面" | ✅ |
| **结构诊断** | 规则引擎查死路/孤立/单薄 + LLM 查情节雷同 | 树一大人工看不出哪里断了 | ✅ |

**「故事圣经」是这个产品的设计核心**：每次生成节点，AI 会从中提取新角色与伏笔并入圣经；
下次续写时把圣经作为上下文喂回去。这让"AI 参与"从"每次重新编"变成"带着记忆编"，
正是它区别于普通"对话框套壳 AI"的地方。

### 模型选择与成本取舍

用账号下**最便宜**的 `deepseek-v4-flash`，并**关闭思考链**（`thinking: disabled`）。实测：

| 配置 | 单次输出 token | 4 次调用总耗时 |
|---|---|---|
| v4-flash + 思考链（默认） | 132~2290（reasoning 占 87%） | 60~90s |
| **v4-flash + 关思考（采用）** | 57~500 | **19.7s** |

关掉后**成本降 2~3 倍、快 3~4 倍**，实测文笔仍能满足需求（伏笔回收、角色一致、选项后果均正常）。
如需更强叙事，`.env` 里 `DEEPSEEK_THINKING=enabled` 一行切回。

## 四、AI 如何参与开发（本次实操的过程）

AI 编程是这个岗位的默认工作方式，这里说明我如何用它、以及如何对它负责：

- **用它快速搭骨架**：Flask 后端、Vue3 前端、递归组件、prompt 工程由 AI 一次性产出，
  把时间留给"判断"而非"打字"。
- **用它做端到端验证**：写了 `smoke_test.py` 跑通"开篇→续写→结局→诊断→存读"全链路；
  用浏览器自动化实际点击走通用户路径（生成、展开、试玩、保存）。
- **识别并修正了 AI 输出的问题**（关键，不是照单全收）：
  1. 冒烟测试发现**结局生成会偶发降级成 mock**——根因是思考链吃满 `max_tokens` 导致 JSON 被截断，
     而代码把截断当成"生成失败"。修正为显式检测 `finish_reason=length`，截断即报错重试而非偷偷换假内容。
  2. AI 初版让模型自己生成分支 `target` id，容易悬空；改为前端用 `child` 字段管理树链接，更可控。
  3. 构建机 esbuild 反复 OOM，AI 判断出是环境内存受限（非代码 bug），改用轻量 terser 配置解决。
- **我对结果负责**：以上每处修改都经过重新测试验证，README 里如实标注了哪些真实、哪些降级。

## 五、完成边界（诚实声明）

**✅ 真实可用**：四个 AI 能力、节点编辑/重roll/删除、结构诊断、试玩通关、JSON 本地持久化、
无 key 时自动降级演示模式。

**⚠️ 使用 mock / 降级**：仅当 `backend/.env` 未配 key，或真实调用失败时，
才走本地模板生成器，且界面右上角明确显示「演示模式」。**配好 key 即为全真实 AI。**

**❌ 明确未做（时间与范围的取舍）**：
- 多用户 / 登录 / 云端存储（当前作品存本地 JSON 文件）
- 一键发布分享链接、配图 / 语音
- 分支合并（多条路径汇入同一节点）——这是我最想补的下一步
- 重型可拖拽节点图（用缩进树代替，省下约 1/3 工作量投到闭环质量上）

**下一步优先级**：① 分支合并 chokepoints → ② AI 以"读者视角"找剧情漏洞 → ③ 导出独立 HTML 试玩包。

## 六、技术栈与架构

Vue 3 + Vite（前端，手写 CSS 无组件库）· Python Flask（后端）· DeepSeek API（大模型）· 本地 JSON 持久化。

```
branch-studio/
├── backend/                 Python Flask
│   ├── app.py               API + 静态托管 + data/*.json 持久化
│   ├── story_engine.py      prompt 工程 / mock 生成器 / 结构诊断
│   ├── llm.py               DeepSeek 客户端（OpenAI 兼容，JSON 模式）
│   └── smoke_test.py        端到端冒烟测试
└── frontend/                Vue 3 + Vite
    └── src/
        ├── store.js         响应式状态 + 生成动作 + 树操作
        └── components/      SetupPanel / NodeCard(递归) / StructurePanel / BiblePanel / PlayMode
```

API Key 只存在于后端 `.env`（已 gitignore），不进浏览器。

## 七、如何本地运行

### 准备
```bash
cd backend
pip install -r requirements.txt        # 需要 Python 3.9+
cp .env.example .env                   # 填入 DEEPSEEK_API_KEY；留空则自动演示模式

cd ../frontend
npm install                            # 需要 Node 18+
```

### 开发模式（前端热更新）
```bash
# 终端1
cd backend && python app.py            # 后端 http://127.0.0.1:5001
# 终端2
cd frontend && npm run dev             # 前端 http://localhost:5173（自动代理 /api）
```

### 生产模式（单端口，推荐演示）
```bash
cd frontend && npm run build           # 产出 dist/
cd ../backend && python app.py         # 直接访问 http://127.0.0.1:5001
```

### 验证后端 AI 全链路
```bash
cd backend && python smoke_test.py     # 打印 开篇/续写/结局/诊断/存读 结果，末行 ALL PASS
```

> 构建若因内存紧张被终止：`vite.config.js` 已配轻量 terser；仍失败可设
> `NODE_OPTIONS=--max-old-space-size=768` 与 `GOMEMLIMIT=300MiB` 后重试。开发模式不受影响。

## 七·补、线上部署（可选，本仓库已配好）

仓库根目录的 `render.yaml` 是 Render 免费部署蓝图，三步上线：

1. 打开 https://render.com → New → Blueprint → 连接本 GitHub 仓库
2. 在环境变量里填 `DEEPSEEK_API_KEY`（不会进仓库）
3. 部署，得到一个 `https://xxx.onrender.com` 链接

> ⚠️ **免费实例的已知限制**（诚实说明）：Render 免费版的文件系统是临时的，
> 每次重新部署或实例休眠后，**作品库中已保存的 JSON 会丢失**；且冷启动首次访问需等 30~60 秒。
> 若要长期保留作品，需接持久磁盘或换成对象存储（属"下一步"未做项）。
> 因此**线上链接用于体验 AI 生成与试玩闭环，作品持久化请以本地运行为准**。

## 八、体验建议（给评审）

1. 打开线上链接（或本地 `python app.py` 后访问 :5001）。
2. 用默认那组悬疑设定，或换成你自己的点子，点「生成开篇」。
3. 挑一个选项点「AI 续写」两三次，观察右侧**故事圣经**如何自动累积角色与伏笔。
4. 点「✦ 结构诊断」，看它标出哪些分支还没展开（死路）。
5. 切「▶ 试玩」，从头点到结局——这是这条路径真正"可体验"的证据。
